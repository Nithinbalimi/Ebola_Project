# 4. PREDICTION

confidence  = round(max(proba) * 100, 2)                   # 87.0%

# 5. RENDER RESULT
if prediction == 1:
    result = 'Positive'   # High Risk — RED
else:
    result = 'Negative'   # Low Risk — GREEN
3. Ensemble Learning — Deep Dive

Ensemble learning is a technique where multiple ML models are trained and their predictions are combined to produce a final, more accurate and robust output.

Why Ensemble? — Analogy
Think of it like a medical panel: Instead of one doctor diagnosing a patient, you consult 4 specialists. Each has their own expertise and perspective. The final decision is based on the majority opinion — this is far more reliable than any single doctor's opinion alone.

1. SVC — Support Vector Classifier

  • What it does: Finds the optimal hyperplane that best separates positive and negative cases in high-dimensional space
  • Kernel: RBF (Radial Basis Function) for non-linear boundaries
  • Preprocessing: Requires StandardScaler (sensitive to feature scale)
  • Strength: Excellent with high-dimensional medical data
  • Weakness: Slow on very large datasets; needs scaling
  • Best for: Small-to-medium medical datasets with clear margins

2. Random Forest Classifier

  • What it does: Builds 100+ Decision Trees on random subsets of data, averages their results
  • Bootstrap Aggregating (Bagging): Each tree trained on different sample → reduces overfitting
  • Feature Importance: Tells which symptoms matter most
  • Strength: Handles missing values, non-linear data, robust to noise
  • Weakness: Slower prediction, less interpretable
  • Best for: Complex symptom interactions

3. Logistic Regression

  • What it does: Applies sigmoid function to predict probability of Ebola positive
  • Formula: P(y=1) = 1 / (1 + e^(-wx+b))
  • Output: Probability between 0 and 1
  • Strength: Fast, interpretable, gives probability scores
  • Weakness: Assumes linear relationship between features and outcome
  • Best for: Baseline model, interpretable results

4. Decision Tree Classifier

  • What it does: Creates a tree of if-else rules based on symptoms
  • Example: IF fever=1 AND bleeding=1 AND contact_EVD=1 → POSITIVE
  • Split criteria: Gini impurity or entropy
  • Strength: Highly interpretable, handles mixed data types
  • Weakness: Prone to overfitting if not pruned
  • Best for: Capturing complex symptom rule combinations

5. VotingClassifier — The Ensemble Combiner

VotingClassifier from scikit-learn combines all 4 models above. There are two voting types:

TypeHow It WorksWhen Used
Hard VotingEach model votes for a class. Majority class wins. (3 vs 1 → Positive)When models don't output probabilities
Soft VotingAverage predicted probabilities. Class with highest average probability wins.When all models support predict_proba() — MORE ACCURATE

5. HTTPS Implementation — How It Works
NORMAL HTTP:
  Browser ──── [sensitive patient data in plain text] ──▶ Server
               ❌ Anyone on the network can read this!

HTTPS (our implementation):
  Browser ──── [🔒 encrypted data] ──▶ SSL Context ──▶ Server
               ✅ Data is encrypted, unreadable to interceptors

HOW SSL HANDSHAKE WORKS:
  1. Browser connects to server on port 8443
  2. Server sends SSL Certificate (server.crt)
  3. Browser verifies certificate (shows warning for self-signed)
  4. Both agree on encryption keys (TLS handshake)
  5. All data encrypted with AES — HTTPS established

OUR SSL SETUP:
  ssl_context = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
  ssl_context.load_cert_chain(certfile='server.crt', keyfile='server.key')
  httpd.socket = ssl_context.wrap_socket(httpd.socket, server_side=True)

🤖 Machine Learning Questions
4
What is Ensemble Learning? Why did you use it?
Ensemble learning combines multiple ML models to produce better predictions than any single model alone. It works on the principle of "wisdom of the crowd" — multiple diverse models covering each other's weaknesses.

I used it because:
  • Medical data is complex — no single model captures all patterns
  • Reduces overfitting and variance
  • More robust to noisy or incomplete data
  • Higher accuracy through combined expertise of SVC, RandomForest, LR, and Decision Tree
Interview Formula: Ensemble = Multiple weak learners → One strong learner
5
What is VotingClassifier? Explain Hard vs Soft Voting.
VotingClassifier is a meta-estimator in scikit-learn that fits multiple classifiers and combines their outputs.

TypeMechanismExample
Hard VotingEach model predicts a class. Majority class wins.SVC=1, RF=0, LR=1, DT=1 → Result: 1 (3 vs 1)
Soft VotingAverage predicted probabilities across all models.Avg P(positive) = 0.73 > 0.5 → Result: Positive
Soft voting is generally more accurate because it uses the confidence level of each model's prediction, not just the final class.
6
Explain how SVM/SVC works.
SVC (Support Vector Classifier) finds the optimal hyperplane that maximally separates two classes in feature space.

Key concepts:
  • Support Vectors: Data points closest to the decision boundary
  • Margin: Distance between the hyperplane and nearest support vectors — SVM maximizes this
  • Kernel Trick: Maps data to higher dimensions to find non-linear boundaries (RBF kernel used here)
  • C parameter: Controls trade-off between margin size and misclassification
Requires StandardScaler — SVM is sensitive to feature scale because it's distance-based.
7
How does Random Forest work?
Random Forest is a Bagging (Bootstrap Aggregating) ensemble of Decision Trees.

Steps:
  1. Create N bootstrap samples (random subsets with replacement)
  2. Train one Decision Tree on each sample
  3. Each tree also considers a random subset of features at each split
  4. For classification: majority vote across all trees
The randomness (data sampling + feature selection) prevents correlation between trees, reducing variance and overfitting.
8
What is StandardScaler and why is it needed?
StandardScaler transforms features to have zero mean (μ=0) and unit variance (σ=1).

Formula: z = (x - μ) / σ

Why needed:
  • SVC: Distance-based — feature with larger range dominates
  • Logistic Regression: Gradient descent converges faster with scaled features
  • Example: age (0-100) vs fever (0-1) — without scaling, age dominates
Random Forest and Decision Tree do NOT need scaling — they're tree-based and use thresholds, not distances.
9
What is LabelEncoder? When did you use it?
LabelEncoder converts categorical text labels into numerical integers so ML models can process them.

In our project: 
sex: ['Male', 'Female'] → [1, 0]
Profession: ['Doctor', 'Nurse', 'Farmer', ...] → [0, 1, 2, ...]
Use LabelEncoder for ordinal or binary categories. For nominal multi-class categories, OneHotEncoder is better to avoid implying false ordinal relationships.
10
What is predict_proba() and how is the confidence score calculated?
predict_proba() returns the probability estimate for each class instead of just the predicted class. 
probabilities = model.predict_proba([[1,0,1,...]])
# Returns: [[0.13, 0.87]]
# 13% chance Negative, 87% chance Positive

confidence = round(max(probabilities[0]) * 100, 2)
# confidence = 87.0%
Not all classifiers support predict_proba(). SVC requires probability=True at initialization to enable it.
11
What is overfitting and how does ensemble learning prevent it?
Overfitting: Model learns training data too well (including noise) and performs poorly on new data.

Ensemble prevents it by:
  • Diversity: Different algorithms have different biases — errors cancel out
  • Averaging (Bagging): Random Forest averages many trees → variance drops
  • Combining: If one model overfits, others compensate through voting
Bias-Variance Tradeoff: Ensemble reduces variance (overfitting) while maintaining low bias.

14
How is the ML model loaded and why is it loaded at startup?
The model is loaded once at module level in views.py, not inside the view function: 
# views.py — TOP LEVEL (loaded once)
ensemble_model = joblib.load(os.path.join(MODEL_DIR, 'ensemble_model.pkl'))

# NOT inside the predict function — that would reload 31MB every request!
Why at startup?
  • Loading 31MB model takes ~2-3 seconds
  • Loading on every request would make the app very slow
  • At module level, it loads once when Django starts and stays in memory
This is a critical performance optimization — always load heavy models at startup.
🔐 Security / HTTPS Questions
15
How did you implement HTTPS? What is SSL/TLS?
SSL/TLS is a cryptographic protocol that encrypts data between client and server.

Implementation steps:
  1. Generated RSA 2048-bit private key using cryptography library
  2. Created X.509 self-signed certificate with IP SAN
  3. Created ssl.SSLContext with PROTOCOL_TLS_SERVER
  4. Loaded cert and key into SSLContext
  5. Wrapped WSGI server socket with SSL
Why custom implementation? django-sslserver uses ssl.wrap_socket() which was removed in Python 3.12. We use the modern ssl.SSLContext API.
16
What is a Subject Alternative Name (SAN) and why did you use it?
SAN is an X.509 certificate extension that specifies additional hostnames or IP addresses the certificate covers.

Without SAN — browsers reject the certificate even if the IP matches the Common Name (CN).

Our certificate has SAN for:
  • localhost — for this PC
  • 127.0.0.1 — loopback IP
  • 10.53.255.177 — local network IP for other devices
Since Chrome 58 (2017), browsers require SAN — CN alone is no longer sufficient for certificate validation.
17
Why does the browser show a security warning for your app?
Our certificate is self-signed — meaning we signed it ourselves rather than having it signed by a trusted Certificate Authority (CA) like DigiCert, Let's Encrypt, or Comodo.

Browser trust chain: 
Trusted CA (DigiCert) → Intermediate CA → Website Certificate ✅ Trusted
Our App (self-signed) → No CA chain → ⚠️ Browser Warning
For production, you'd use a free certificate from Let's Encrypt. Self-signed is fine for development and internal network use. The data IS encrypted — the warning is only about identity verification.

What is CSRF and how does Django handle it?
CSRF (Cross-Site Request Forgery) is an attack where a malicious site tricks a user's browser into making unauthorized requests to another site where the user is authenticated.

Django's protection:
  • Generates a unique CSRF token for each session
  • Embeds it in forms: {% csrf_token %}
  • Validates the token on every POST request
  • Request without valid token → 403 Forbidden
In our form's HTML: <form method="POST"> {% csrf_token %} ... </form>

What is cross-validation and did you use it?
Cross-Validation (k-fold) splits data into k equal parts, trains on k-1 parts and tests on the remaining 1 part, repeating k times. It gives a more reliable accuracy estimate than a single train/test split. 
# 5-fold cross validation example
from sklearn.model_selection import cross_val_score
scores = cross_val_score(model, X, y, cv=5, scoring='f1')
print(f"F1: {scores.mean():.3f} ± {scores.std():.3f}")
Cross-validation ensures the model doesn't overfit to a particular train/test split and gives confidence the model generalizes well.
